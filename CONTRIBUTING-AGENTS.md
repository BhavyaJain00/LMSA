# Build contract for feature implementers

This document is the shared contract for everyone implementing features in this LMS. Read it fully before writing code. The app is a **Next.js 16 (App Router) + React 19 + TypeScript (strict) + Tailwind CSS 4** rebuild of Frappe LMS with **fully custom components**.

## Hard rules

1. **No third-party UI, player, form, icon, markdown, date or state libraries.** Everything is hand-built. Allowed runtime deps: `next`, `react`, `react-dom`, `server-only`. (`zod` exists in node_modules as a transitive dep — do not import it.)
2. **Never embed YouTube/Vimeo.** Videos are self-hosted files (or any direct `.mp4/.webm` URL) played through the custom player in `src/components/player` (`VideoPlayer`) or, on lesson pages, `src/components/learn/lesson-video.tsx` (`LessonVideo`, which records watch progress).
3. **Next.js 16 conventions** (breaking vs. older versions):
   - `params` and `searchParams` are **Promises**: `const { slug } = await props.params`.
   - Use the global typed helpers: `PageProps<"/courses/[slug]">`, `LayoutProps<"/">`, `RouteContext<"/api/x/[id]">` (no import needed; run `npx next typegen` after adding routes).
   - `cookies()` / `headers()` are async. `middleware.ts` is now `src/proxy.ts` (already exists).
   - Server Actions live in `src/lib/actions/*.ts` with `"use server"` at the top and return `ActionResult<T>` from `src/lib/types.ts` (or call `redirect()`). Use `useActionState` in client forms.
   - After mutations call `revalidatePath(...)`. Use `setFlash(message, tone)` from `src/lib/flash.ts` before a `redirect()` to show a toast on the next page.
4. **Auth & permissions** (`src/lib/auth/session.ts`): `getCurrentUser()` (memoized), `requireUser(nextPath)`, `requireRole([...])`, `hasRole`, `isAdmin`, `isModerator`, `isCreator`, `isEvaluator`, `isStaff`. Roles: `student | course_creator | moderator | batch_evaluator | admin` (admin implies all). Course-level checks: `canManageCourse(user, course)`, `canViewCourse` in `src/lib/data/courses.ts`. **Every Server Action must re-check permissions**; never trust client input.
5. **Data access** goes through `src/lib/db/store.ts`: `getDb()`, `all(name)`, `findById(name, id)`, `findOne`, `filter`, `count`, `insert`, `insertMany`, `update(name, id, patchOrFn)`, `remove`, `removeWhere`, `mutate(db => …)` (serialized, auto-persisted), `getSettings()`. Collection names and all entity shapes are in `src/lib/types.ts` — **do not change existing types**; you may add optional fields only if unavoidable and must mention it in your report. Ids come from `uid("prefix")` in `src/lib/utils.ts`.
6. **Shared services** (use them instead of re-implementing): 
   - `src/lib/services/progress.ts`: `completeLesson`, `setLessonStatus`, `getCompletionRequirements`, `recalculateCourseProgress`, `issueCertificate`.
   - `src/lib/services/notifications.ts`: `notify`, `notifyMany`, `notifyModerators`, `getNotifications`, `getUnreadCount`.
   - `src/lib/services/badges.ts`: `evaluateBadges(userId, event, value?)`, `grantBadge`, `getUserBadges`.
   - `src/lib/services/activity.ts`: `logActivity`, `getStreak`, `getActivityHeatmap`.
   - `src/lib/data/courses.ts`: `getCourseBySlug`, `getCourseSummaries(viewer, filter)`, `getCourseSummary`, `getCourseOutline(course, viewer)` (chapters → lessons with `status`, `locked`, `chapterNumber`, `lessonNumber`), `findLessonByNumbers`, `parseLessonRef`, `lessonHref`, `getCourseProgress`, `getNextLesson`, `getEnrollment`, `getCourseReviews`, `getRatingBreakdown`, `getCategories`.
   - `src/lib/data/users.ts`: `getPublicUser`, `getPublicUsers`, `getUserMap`, `getUserByUsername`, `getUserByEmail`, `listUsers`, `listInstructors`, `listEvaluators`.
7. **UI kit** in `src/components/ui` — use these, don't fork them: `Button`, `ButtonLink`, `IconButton`, `buttonClasses` (button.tsx); `Input`, `Textarea`, `Select`, `Checkbox`, `Switch`, `Label`, `Field`, `FormError`, `FormSuccess`, `RadioCard` (input.tsx); `Card`, `CardHeader`, `CardBody`, `CardFooter`, `StatCard`, `PageHeader`, `SectionTitle` (card.tsx); `Badge`, `Tag`, `StatusBadge` (badge.tsx); `Avatar`, `AvatarGroup`; `ProgressBar`, `ProgressRing`; `Skeleton`, `CardSkeleton`, `ListSkeleton`, `EmptyState` (skeleton.tsx); `Table`, `THead`, `TBody`, `TR`, `TH`, `TD`, `TableEmpty`; `Dialog`, `ConfirmDialog` (client); `Tabs` (URL-driven: `href` or `?tab=value`), `SegmentedControl` (client); `Dropdown`, `Tooltip` (client); `useToast`/`ToastProvider` (client); `Icon.<Name>` from icons.tsx (custom SVG set — add new icons there if needed, same style). Markdown: `<Markdown content={md} />` from `src/lib/markdown.tsx`.
8. **Styling**: Tailwind 4 with semantic tokens defined in `src/app/globals.css`: colors `surface`, `surface-1/2/3`, `border`, `border-strong`, `ink`, `ink-muted`, `ink-faint`, `accent`, `accent-fg`, `success`, `warning`, `danger`, `info`; radius `rounded-card`; shadows `shadow-card`, `shadow-pop`. Dark mode works automatically through these tokens (never hardcode gray-900 etc.). Use `cn()` from utils. Pages are mobile-first and must work at 375px width.
9. **Layouts**: pages under `src/app/(app)/…` get the sidebar+header shell automatically. `src/app/(auth)/…` is the minimal auth layout. `src/app/(learn)/…` is for the full-width lesson player (create its own layout without the shell if you own it). Public printable pages (certificate) go under `src/app/(public)/…` with their own layout.
10. **Uploads**: the upload route handler is `POST /api/upload` (multipart `file` field, optional `kind=video|image|document`), returns `{ ok, url, name, size, type }`. Files are stored under `storage/uploads` and served from `/uploads/<name>` by `src/app/uploads/[...path]/route.ts`. Use the `<FileUpload>` client component in `src/components/ui/file-upload.tsx` (props: `name`, `accept`, `kind`, `value`, `onChange(url)`, `label`). If these do not exist yet when you start, the "admin-courses" implementer owns creating them; others should code against this interface.
11. **Quality bar**: `npx tsc --noEmit` and `npx eslint src` must pass for the files you own. Handle loading/empty/error states. Use semantic HTML and accessible labels. Do not leave TODOs or placeholder text; implement the real behavior.
12. **File ownership**: only create/edit files inside the directories assigned to you. Never edit files in `src/lib/{types,utils,config,markdown,flash,nav}.ts(x)`, `src/lib/db/*`, `src/lib/auth/*`, `src/components/ui/*`, `src/components/player/*`, `src/components/layout/*`, `src/app/layout.tsx`, `src/app/globals.css`. If you need a change there, describe it precisely in your final report instead.

## Conventions

- Route paths mirror Frappe LMS: `/courses`, `/courses/[slug]`, `/courses/[slug]/learn/[ref]` (ref = `chapterNumber-lessonNumber`, e.g. `1-3`), `/batches`, `/batches/[slug]`, `/programs`, `/programs/[slug]`, `/quiz/[id]`, `/assignments/[id]`, `/exercises/[id]`, `/jobs`, `/jobs/[slug]`, `/user/[username]`, `/certificates/[code]`, `/certified-members`, `/statistics`, `/notifications`, `/dashboard`, `/billing/[type]/[id]`, `/persona`, `/settings`. Admin pages live under `/admin/...`.
- Server Components by default; add `"use client"` only for interactivity, and keep client components small (forms, editors, players, menus).
- Forms: plain `<form action={serverAction}>` with `useActionState` for errors/pending. Read fields with `fd(formData, "name")`, `fdBool`, `fdNumber` from utils.
- Dates are ISO strings; day-only values are `YYYY-MM-DD`. Use `formatDate`, `formatDateTime`, `formatClock`, `relativeTime`, `formatDuration`, `formatTime`, `formatPrice` from utils.
- Money is stored in the smallest unit (cents).
- Wording: friendly, concise, sentence case. Empty states explain what will appear and offer the primary action.
